# CANNABIS v1.6.0

## 今回の変更
- PC（幅900px以上）は左サイドバー型レイアウトに変更。iPhoneは従来の下部ナビゲーションを維持。
- PCヘッダーに「モニター表示」ボタンを追加。別タブで `?tv=1` の専用スケジュール画面を開く。
- モニター表示は全社員の1日分ガントチャートを全画面向けに表示。日付・現在時刻を大きく表示し、現在時刻線を1秒ごとに更新。日付が変わると当日表示に切り替える。
- 時間軸は00:00〜30:00（翌日06:00）。翌日02:00は26:00として表示。
- Firestore `appData/shared` に業務データを保存し、リアルタイムリスナーでiPhone・PC間のデータ変更を同期。
- 初回同期時、Firestoreに共有データがまだない場合は、その端末のlocalStorageデータを初期データとしてFirestoreへ登録。
- 既存のiPhone画面・既存業務機能は、PC/TV表示とデータ同期以外の変更を避けて維持。

## Firebaseで必要な作業
1. Firebase ConsoleのFirestore Databaseで「ルール」を開く。
2. 同梱の `firestore.rules.txt` の内容に置き換えて公開する。
3. 既存どおり `employees/{GoogleログインUID}` に、ログインを許可する社員の `email` / `active: true` 等が登録されていることを確認する。
4. GitHub PagesへこのZIPの中身をアップロードする（既存の `icons` フォルダ名を変更しない）。

## 初回データ移行の注意
Firestoreの共有データが空の状態で初回ログインした端末のlocalStorageが、共有データの初期値として登録されます。**既存の業務データが入っているiPhoneで最初にログイン・同期を行ってください。** PCを先に初回起動すると、PC側のデータが初期値として登録される可能性があります。

## 重要な制約・未検証事項
- 現版は既存コードへの影響を抑えるため、業務データ全体をFirestoreの1ドキュメント `appData/shared` に格納する方式です。Firestoreの1ドキュメント上限（1MiB）があり、データ量が増えたらコレクション分割が必要です。
- 複数端末が同時に同じデータを編集した場合、最後に保存した全体データが優先され、同時編集内容が上書きされる可能性があります。リアルタイム閲覧・通常の順次編集向けの初期同期方式です。
- Firestoreルールは有効な社員の共有データ読み書きを許可します。細かな役割別のデータ書込制限は、現段階では画面側の権限制御です。厳密な権限分離にはデータ構造の分割とルール追加が必要です。
- 既存の社員認証用 `employees/{uid}` ドキュメントは引き続き別管理です。社員マスター画面で社員を追加しただけではGoogleログイン許可にはなりません。
- GitHub Pagesへのデプロイ後、Firebase Consoleでルールを公開して初めて共有同期が動作します。設定作業なしで自動的に本番接続が完了するわけではありません。
